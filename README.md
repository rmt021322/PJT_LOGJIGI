# LOGJIGI · 블로거를 위한 검색비서

이 앱의 이름은 LOGJIGI(로그지기)입니다.

네이버 블로그 ID를 화면에서 입력하고, 공개된 글을 읽어 블로그 안의 기록을 찾고 최근 관심 주제를 살펴보는 Flask 앱입니다. 웹 검색 화면은 준비 중 안내만 표시합니다. 로그인은 필요하지 않습니다.

## 빠른 실행

압축을 풀고 **app.py와 requirements.txt가 있는 PJT_LogJIGI 폴더**에서 실행하세요.

```bash
python -m venv .venv
# Windows Git Bash
source .venv/Scripts/activate
python -m pip install -r requirements.txt
python app.py
```

PowerShell 활성화: `.\.venv\Scripts\Activate.ps1`
macOS/Linux 활성화: `source .venv/bin/activate`
브라우저 주소: http://127.0.0.1:5000 / 종료: 터미널에서 Ctrl+C
Python 3.9 이상을 사용하세요. `.bat` 없이 `python app.py`로 실행합니다. 실행하면 브라우저 창도 열립니다. 서버가 켜져 있는 동안 터미널 창을 유지하세요.

업데이트 후 `python -m pip install -r requirements.txt`를 한 번 실행해 주세요. 태그에서 조사를 분리하기 위해 한국어 형태소 분석기 kiwipiepy가 추가됐습니다. 첫 설치에는 모델 패키지를 함께 다운로드하며, 분석기는 첫 태그 분석 때 한 번만 준비됩니다.

## 화면 흐름

1. **블로그 연결:** ID 또는 `https://blog.naver.com/아이디` 주소 입력. 특정 블로그 ID를 config에 미리 쓸 필요가 없습니다.
2. **행위 선택:** ‘내 블로그 글 찾기’ 또는 ‘웹에서 최근 자료 찾기’를 선택합니다. 이 화면 진입 시 공개글 분석이 이미 백그라운드에서 진행됩니다.
3. **블로그 검색:** 질문에서 핵심 단어를 정리하고 제목 우선·본문 근거 확인을 거쳐 관련 글을 최대 3개 보여줍니다. 결과가 1개면 1개만 제시하고, 없는 경우에는 없다고 안내합니다.
4. **웹 검색(준비 중):** 선택하면 준비 중 안내를 보여줍니다. 관심 키워드를 클릭해도 검색 요청을 보내지 않습니다.

오른쪽 **블로그 노트는 2·3-1·3-2 화면에서 공통**입니다. 화면 이동은 분석을 재시작하지 않으며, 검색 결과도 각 화면에 유지됩니다. 웹 검색 안내 화면은 블로그 본문 분석이 끝나기 전에도 열 수 있습니다. 블로그를 바꾸면 이전 분석과 결과가 초기화됩니다.

## 관심사와 인기 정보의 의미

- 관심 키워드는 **최근 작성글 12개(설정 가능)**의 제목과 읽을 수 있는 본문에서 추정합니다. 형태소 분석으로 조사·어미를 제외하고 명사·고유명사·외국어 중심으로 정리해 **최대 5개**만 표시합니다. 예: 게임에서는 → 게임. 같은 명사의 조사 변형은 하나의 태그로 집계합니다. 실제 검색 유입어·검색량·급상승 순위는 아닙니다. 같은 단어가 등장한 글 수와 근거 글 제목을 표시합니다(키워드에 마우스를 올리면 확인).
- 분석 범위는 ‘최근 작성글 N개’입니다. 오래된 블로그도 최근 12개가 수개월 전 글일 수 있습니다. 글 날짜를 함께 표시하며 최근 7일 동안 작성된 글로 가장하지 않습니다.
- 공개 글 목록에 누적 조회수가 제공될 때만 ‘최근 분석 글 중 공개된 누적 조회수’ 기준으로 정렬합니다. 조회수가 제공되지 않으면 숫자를 만들어내지 않고 **최근 공개글**을 보여줍니다. ‘요즘 인기글’이라는 기간별 인기 통계는 제공하지 않습니다.
- 실제 유입 검색어·기간별 인기글은 네이버의 운영자 통계 영역에 해당합니다. 현재 앱은 로그인 정보나 비공개 통계에 접근하지 않습니다.

## 블로그 검색의 관련성 재확인

입력된 핵심 주제의 조건을 모두 확인합니다. 예를 들어 ‘학은제 수강신청’은 ‘학은제’만 있는 글로 채우지 않습니다. 제목 일치 결과를 우선하고, 본문에서만 찾은 결과에는 일치 단어 주변의 발췌를 붙입니다.
긴 본문(1,200자 초과)에서 제목과 관련 없이 한 번 스쳐 언급한 주제는 제외합니다. 이는 규칙 기반 검증이며 생성형 AI가 의미를 판정하는 방식은 아닙니다. 엄격한 검증 때문에 본문에만 드물게 언급한 적합한 글도 제외될 수 있습니다.

검색 결과 3개 제한은 **표시 개수**입니다. 공개글 목록 전체를 읽고 본문 확인을 시도한 뒤 추천합니다. 일부 수집 실패나 설정한 한도 도달은 화면에 표시합니다. 본문 영역만 읽어 메뉴·댓글·로그인 페이지가 검색 결과로 섞이지 않게 합니다.

## 웹 검색은 준비 중

이번 버전에서는 Google 일반 검색·Google 뉴스·유료 검색 API를 **호출하지 않습니다.** 웹 검색 화면에는 준비 중 안내만 표시하며 입력창과 실행 버튼도 비활성화했습니다.
향후 연결 실험을 위한 `back/web_search.py`는 보존했지만 현재 서버에서 import하거나 실행하지 않습니다. API 키를 설정할 필요가 없습니다.

추후 기능 선택 시 참고:

- 검색 결과의 제목·링크를 찾는 기능은 검색 API가 적합합니다.
- 검색 관심도 추이를 보는 Trends 기능은 별도의 기능입니다.
- Google Custom Search JSON API는 신규 고객에게 제공되지 않으며 기존 고객도 2027-01-01까지 대체 솔루션으로 전환해야 한다고 안내합니다: https://developers.google.com/custom-search/v1/overview
- pytrends는 비공식이며 원본 저장소가 2025-04-17 보관 처리됐습니다: https://github.com/GeneralMills/pytrends

## 데이터 유지와 범위

파일·DB·브라우저 저장소에 글을 저장하지 않습니다. 화면 이동 시 같은 결과를 쓰기 위해 선택한 블로그의 글·분석 결과를 **서버 메모리에 연결별로 임시 유지**합니다. ID 변경 시 기존 연결을 취소하고 제거합니다. 서버 종료 또는 45분 동안 사용하지 않은 연결도 만료됩니다. 서로 다른 연결의 블로그 데이터는 섞이지 않습니다. 공개글을 재확인하려면 블로그를 다시 연결하세요. 이전 실행에서 가져온 글을 재사용하지 않습니다.

동시에 최대 8개 연결, 한 연결에서 본문은 최대 3개씩 요청합니다. 공개 목록 연결은 비공식 웹 응답에 의존하므로 네이버 구조 변경에 따라 수정이 필요할 수 있습니다. 현재 버전은 로컬 실행용이며 외부 공개 서비스의 인증·사용량 제한·배포는 포함하지 않습니다.

## 설정과 파일

config.json에는 추천 개수(limit, 최대 3), 이미지와 말풍선(states), 관심사 분석 글 수(insight_recent_posts), 수집 한도만 둡니다. blog_id는 화면에서 입력합니다.

- `live_max_pages`: 200 / `live_timeout_seconds`: 120 — 공개 글 목록의 안전 한도. 초과하면 일부 목록이라는 안내를 표시합니다.
- `body_max_posts`: 0 / `body_timeout_seconds`: 0 — 기본은 본문 전체 개수·총 시간으로 조기 중단하지 않음. 각 요청의 연결·응답 시간과 크기는 별도 제한합니다.
- `body_workers`: 3 — 한 연결에서 동시에 확인하는 최대 본문 수.
- `insight_recent_posts`: 12 — 관심 키워드를 추정할 최근 작성글 수. 전체 블로그 검색 범위를 제한하지 않습니다.

app.py: 연결·상태·블로그/웹 검색 API / back/sessions.py: 독립적인 백그라운드 분석과 임시 메모리 연결 / insights.py: 관심사 추정 / relevance.py: 추천 재검증 / crawler.py·parser.py: 공개글 수집과 본문 추출 / web_search.py: 실행하지 않는 향후 웹 검색 어댑터 / static/script.js: 화면 분기와 공통 노트 유지.
기존 back/main.py의 독립 파이프라인과 테스트도 보존했습니다. 브라우저 앱에서는 선택한 연결의 분석 결과를 재사용해 동일 글을 반복 수집하지 않습니다.

## 검증

```bash
python -m unittest discover -s tests -v
```

자동 테스트는 ID 검증·연결 분리/만료·백그라운드 분석·최근 글 범위·키워드 관련성·결과가 3개 미만인 경우·웹 검색의 준비 중 안내와 외부 요청 미실행을 포함합니다. 웹 검색 어댑터 자체의 테스트도 별도로 남아 있지만 활성화된 제품 기능은 아닙니다. 외부 서비스 응답은 항상 달라질 수 있으므로 실연결 검증 결과와 자동 테스트 결과를 구분하세요.


## 목록·관심사 분석이 안 될 때

글 목록 수집과 관심 키워드 분석의 오류를 구분해 표시합니다. 키워드 분석이 실패해도 이미 읽은 최근 글 목록과 글 검색은 유지합니다. 분석기를 준비하는 동안에도 목록·진행 상태를 조회할 수 있습니다.

| 코드 | 확인할 부분 |
|---|---|
| LIST_TIMEOUT | 글 목록 요청이 시간 초과됨 |
| LIST_RESTRICTED | 서버가 403/429로 요청을 제한함. 반복 요청이나 우회를 시도하지 말고 중단 |
| LIST_FORMAT / LIST_FAILED | 목록 응답 형식 또는 목록 연결 문제. 터미널의 같은 코드 오류를 확인 |
| KEYWORD_DEPENDENCY | 한국어 분석기 로딩 문제. 현재 가상환경에서 `python -m pip install -r requirements.txt` 실행 |
| KEYWORD_FAILED | 관심 키워드 분석 중 오류. 읽은 글 목록과 검색은 계속 사용 가능 |
| BODY_FAILED | 본문 일부를 읽지 못함. 이미 수집한 글 범위에서 검색 |
| CONFIG_FAILED | config.json 등 실행 설정을 읽거나 해석하지 못함 |

이 안내만으로 특정 블로그의 실패 원인을 확정할 수는 없습니다. 오류 코드와 터미널 기록으로 실패 단계를 확인하세요.
