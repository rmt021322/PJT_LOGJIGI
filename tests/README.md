# tests 폴더는 왜 있나요?

이 폴더는 실행할 앱의 검색 데이터가 아니라, 코드를 바꾼 뒤 기존 동작이 망가지지 않았는지 확인하는 개발용 검증 코드입니다. `python app.py`는 이 폴더를 읽거나 테스트용 글을 검색 결과로 사용하지 않습니다.

고정된 글 제목·ID·날짜·정답은 **테스트 입력과 기대값**입니다. 예를 들어 긴 여행 글에 ‘학은제’가 한 번 언급된 상황을 일부러 만들고, ‘학은제’ 검색에서 그 글이 제외되는지 확인합니다. 데이터가 매번 달라지면 같은 조건을 반복 검증할 수 없기 때문에 고정합니다.

`patch`, `MagicMock`은 네이버에 실제 요청하는 대신 시험용 응답을 넣는 도구입니다. 네이버 장애·인터넷 속도·블로그 글 수정과 관계없이 페이지 누락, 중복, 비공개 글 제외, 연결 오류 같은 조건을 재현합니다. 모의 응답을 쓴 테스트 통과는 실제 네이버 연결 성공이나 전체 검색 품질을 뜻하지 않습니다.

| 파일 | 확인하는 부분 | 한계 |
|---|---|---|
| test_app.py | 현재 앱의 API, 연결 분리, 입력 검증, 추천 결과 | 대부분 모의 응답을 사용하며 브라우저에서 클릭하지 않음 |
| test_crawler.py | 공개 목록 페이지·중복·실패 응답 처리 | 이름을 test_live.py에서 변경. 실제 네이버에 접속하는 검사는 아님 |
| test_body_search.py | 본문 추출, 제목 우선, 실패 시 안내 | 일부는 기존 독립 pipeline 함수의 회귀 검사이며 현재 화면 전체 검사는 아님 |
| test_search_scope.py | 검색 범위와 뒤쪽 글의 검색 누락 방지 | 모의 문서를 사용하며 실제 모든 공개글 수집을 보장하지 않음 |
| test_interest_tags.py | 실제 형태소 분석의 조사 제외·최대 5개·브랜딩 | 현실의 모든 문장에서 태그 품질을 보장하지 않음 |
| test_failure_stages.py | 목록 오류·분석기 오류 구분, 분석 실패 시 목록 유지, 상태 조회 잠금 | 모의 실패를 재현하며 특정 블로그에는 요청하지 않음 |
| test_ui_contract.py | JavaScript가 참조하는 HTML ID가 존재하는지 | JavaScript 실행·클릭·화면 배치는 검사하지 않음 |

이번 화면 연결 문제는 `connectError` 영역이 삭제됐는데 JS가 계속 참조해서 생겼습니다. API 중심 테스트만으로는 놓칠 수 있는 유형이라, 화면과 스크립트의 ID 연결을 검사하는 항목을 추가했습니다.

실행은 app.py가 있는 폴더에서:

```bash
python -m unittest discover -s tests -v
```

실제 외부 연결과 브라우저 동작은 별도로 확인해야 합니다. 테스트가 전부 통과했다는 사실과 실제 서비스에서 잘 작동한다는 판단은 구분해서 보세요.
